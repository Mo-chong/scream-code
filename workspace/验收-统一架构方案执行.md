## 逻辑验证

### 优化 C — contentHash 去重 ✅
- 注入流程：stepInjectedVariants 去重(同一步) → **contentHash 去重(跨步)** → VariantScheduler 配额 → 执行
- 跨步相同 variant 相同内容 prefix 60 字符 → 跳过
- compaction 后内容失效 → reset
- 不同 variant 不受影响

### 优化 D — level-aware cooldown ✅ 已预存在 variant-registry.ts
- VARIANT_META.minStepGap 已实现 S=0, prepare=3-4, post=3-4, step_after=4-5
- 方案文档中的平均冷却值（S:0 / A:2 / B:3 / C:5）与代码实际相符

### 未知 variant 告警 — ✅
- 新增 variant 时忘记更新映射表 → console.warn 提示 → 无静默 fallback 陷阱

### GrowthPredictor EMA — ✅
- 稳定序列：5×100 delta → EMA=100 → 120（与简单平均一致）
- Spike 场景：0,0,100,300 → EMA=144 → 173（比简单平均的 120 更敏感）
